# FormaProof positioning and public competitor evidence

## Product promise

The functional PDF entry starts at `/spot`. Users upload their own technical documents and inspect actual sourced evidence. Public reference documents support the bounded search index and automated verification; they are not a new demo page or a preloaded presentation flow. The existing project and measured-parts tools remain available.

**From a technical document to editable components and patent evidence.**

FormaProof helps an engineer review what a document actually says, create simplified measured parts where geometry permits, and investigate existing technologies with explicit sources. The first experience is one project with a chosen goal: patent research or part design. General patent research does not require a physical model.

The core navigation is **Nouveau projet / Mes projets / Veille**. Advanced CAD, research, reports and integration tools remain available under Resources. Public API/MCP identifiers, repository names and existing routes stay compatible.

## Public competitor observations — 2026-10-25

Anonymous HTTP requests from this environment to `https://patentradar.io/`, `/features`, `/pricing` and `/robots.txt` returned HTTP **401**, `text/plain`, body `401 Unauthorized`. `https://www.patentradar.io/` redirected to the same protected apex. The response advertised `WWW-Authenticate: Basic realm="Patentradar beta"`. No authentication bypass or private-app probing was attempted.

Consequently, the competitor's feature count, pricing, data coverage, CAD features and search quality are **not verified**. These observations do not establish that the competitor lacks any capability. Do not claim FormaProof is better, more complete, cheaper or more accurate without a comparable evaluation and accessible evidence.

## Defensible differentiation and its limits

| Capability in FormaProof | Honest scope |
| --- | --- |
| Document interpretation | Source pages and quotations; unknown dimensions remain unknown. External AI requires configuration and consent. |
| Editable mechanical components | Simplified parametric shapes and user-entered or source-supported measurements; arbitrary complete machine reconstruction is not promised. |
| Actual CAD geometry and export | Browser OpenCascade generates solids and STEP/STL output; geometric validity does not establish engineering or manufacturing fitness. |
| Evidence-linked patent research | Short reviewed concepts, recorded provider outcomes, passages and source links; patent and scientific records remain distinguished. |
| Design iteration | Components can inform research and be revised; source/reconstruction limits remain visible. |
| Monitoring | Saved searches and user-triggered watch checks; no automatic newsletter or global background monitoring is implied. |

The meaningful comparison is the continuity of **document → reviewed features/parts → design → patent evidence → revised design**. The initial patent ranking is lexical; optional AI assistance must not be presented as comprehensive semantic search. Provider availability and jurisdiction coverage are partial. An empty search is not freedom-to-operate clearance.

## Next product evidence to establish

1. Demonstrate a real document-to-part-to-research journey without losing the source or project state.
2. Evaluate retrieval on a small public set of engineering briefs with identified relevant patent records and independently reviewable passages.
3. Show why a result is relevant to a particular function or component and what information is unavailable.
4. Measure result usefulness and successful task completion, rather than compare differently defined feature counts.

No blanket legal conclusions, automatic royalty estimates or permission to manufacture are part of the product promise.
